# v00.227.000 — anchor scroll-padding (sticky nav 가림 해소)

## 사용자 요청
> 이전 작업 이어서 해줘 (no clarifying questions)

직전 사이클(v00.226 메타 현행화)이 깨끗하게 마무리된 상태에서 ROADMAP §큐1
"anchor scroll-margin-top" 항목을 진행. 가장 작고 well-defined 한 후속.

## 문제

`pages/ColumnPage.jsx:257` 의 `<h2 id="col-comments">` 같은 native anchor 로
브라우저 hash 진입 (`/?p=column#col-comments`) 또는 element.scrollIntoView()
호출이 일어나면, 도착점이 sticky `.nav` (72px desktop / 64px mobile, `top: 0`)
아래로 가려져 사용자가 직접 스크롤을 더 내려야 함.

기존 코드에서:
- `scrollMarginTop: 24` 가 [pages/AuthAdminPage.jsx:6589](pages/AuthAdminPage.jsx#L6589),
  [pages/AuthAdminPage.jsx:6628](pages/AuthAdminPage.jsx#L6628) (admin KMS 카드)
  에만 인라인으로 박혀 있고, 사이트 전반에는 미적용.
- ColumnPage 의 prev/next 는 `setSelectedId` state 우회로 자체 해결.
- 관리자 KMS 외 모든 native anchor (`#col-comments`, `#col-comment-input`,
  `#col-search`) 가 무방비.

## 변경

### 1. `styles.css` — `html { scroll-padding-top }` 글로벌 1회

```css
html { scroll-padding-top: 88px; }                              /* 72 + 16 */
@media (max-width: 720px) { html { scroll-padding-top: 80px; } } /* 64 + 16 */
```

`scroll-padding-top` 은 스크롤 컨테이너에 부여하는 표준 속성으로,
hash 진입 · element.scrollIntoView() · 브라우저 "이전 위치 복원" 모두에 적용.
요소마다 `scroll-margin-top` 을 부여하는 것보다 한 곳에서 사이트 전역 정합.

기존 인라인 `scrollMarginTop: 24` (admin KMS) 는 그대로 유지 — 더 큰 값이
우선되어 자동으로 안전. (24 < 88 이므로 글로벌이 우선 적용.)
