# v00.264.003 — 게시글 페이지당 갯수 선택 (홈 + 관리자 패리티)

## 사용자 요청 원문

> 홈페이지에서 구현된 기능은 관리자 페이지에서도 구현되어야하고, 관리자페이지에서만 구현된 기능은 홈페이지에서 구현할지 물어보는 규칙을 추가해.
>
> 그리고 커뮤니티에서 게시글 볼 떄 한 페이지에 보이는 글의 갯수를 선택할 수 있게해줘. 최소 10개, 30개, 50개, 100개 순으로.

## 처리

규칙 측은 메모리 `feedback_feature_parity_home_admin.md` 로 저장 완료 ([MEMORY.md](../../.claude/projects/-Users-jimmy-macmini-Desktop-VS-Code-kingsroad/memory/MEMORY.md)). 본 plan 은 갯수 선택 기능을 홈 + 관리자 양쪽에 동시 적용 (= 신규 규칙 첫 적용 사례).

## 진단

### 홈 [pages/CommunityPage.jsx](../pages/CommunityPage.jsx)

[line 517](../pages/CommunityPage.jsx#L517) `const POSTS_PER_PAGE = 10;` 고정. `filtered.slice(pageStart, pageStart + POSTS_PER_PAGE)` 로 페이지 산출.

### 관리자 [pages/AuthAdminPage.jsx](../pages/AuthAdminPage.jsx)

[line 5857 CommunityPostsAdminPanel](../pages/AuthAdminPage.jsx#L5857) — `visible` 배열을 그대로 `.map` 으로 렌더. 페이지네이션 자체가 없음 → 게시글 1000건 이상 시 한 번에 모두 그려져 무겁다는 잠재적 문제 존재.

## 변경 방안

### 1) 홈 `CommunityPage`

- `POSTS_PER_PAGE` 상수 폐기 → `[postsPerPage, setPostsPerPage]` state (기본 10).
- localStorage `bgnj_community_posts_per_page` 에 사용자 선택 보존.
- 정렬 select 옆에 "한 페이지: [10 ▼ / 30 / 50 / 100]" select 신설.
- per-page 변경 시 page 1 로 자동 리셋.
- 페이지네이션·번호 매기기 로직 그대로 (POSTS_PER_PAGE 만 변수화).

### 2) 관리자 `CommunityPostsAdminPanel`

- 새 state: `page`, `pageSize` (기본 30 — admin 은 더 많이 본다고 가정).
- localStorage `bgnj_admin_posts_per_page` 보존.
- 검색바 옆에 동일한 갯수 select.
- `visible` → `pagePosts = visible.slice(start, start+pageSize)` 로 분할.
- 하단에 페이지네이션 nav (홈과 같은 모양).
- 페이지 이동/검색/필터/per-page 변경 시 page 리셋.
- 선택 일괄 작업은 "표시된 페이지" 기준 (현재도 `visible.every` 패턴이라 변경 없음 — `visible` 자체를 `pagePosts` 로 좁히면 페이지 단위 선택).

### 3) 신규 규칙 적용 메모

홈·admin 동시 변경. 검증 시 양쪽 모두 확인.
