## 2. React production SRI

unpkg 의 react@18.3.1 production.min.js / react-dom@18.3.1 production.min.js 의 SHA-384 SRI 해시는 별도 fetch 가 필요. wrangler/curl 로 하지 말고 cdn 의 표준 SRI 검증 — 새 hash 자동 fetch 확인.

본 사이클에선 SRI **임시 제거** 후 동작 확인 → 다음 사이클에서 SRI 재부착. 정적 호스팅 + CSP 가 강한 게이트라 단기 SRI off 는 허용 가능 (unpkg 신뢰 + HTTPS).

또는 동시에 SRI 재계산. 빠르게: `curl -sL https://unpkg.com/react@18.3.1/umd/react.production.min.js | openssl dgst -sha384 -binary | openssl base64 -A`.

## 3. defer 부착

```html
<script defer src="api.js?v=00.161.000"></script>
<script defer src="data.js?v=00.161.000"></script>
... (모든 외부 script 에 defer)
<script defer src="boot.js?v=00.161.000"></script>
```

defer 는 문서 순서 보장 + DOMContentLoaded 직전 실행. React → DOMPurify → data → api → pages → boot 순서가 문서 순서와 같으므로 정합. inline `<script>` 와 `<script type="module">` 는 defer 미적용 (script type=module 은 자동 defer-equivalent).

## 4. PII sanitize

```js
_PII_KEYS_PROFILE: ['phone', 'birthdate', 'address', 'addressDetail', 'zip'],
_sanitizeForCache(user) {
  if (!user) return null;
  const { profile, ...rest } = user;
  if (!profile) return rest;
  const cleanProfile = { ...profile };
  for (const k of this._PII_KEYS_PROFILE) delete cleanProfile[k];
  return { ...rest, profile: cleanProfile };
},
_writeCache(user) {
  try {
    if (user) localStorage.setItem(this._SESSION_KEY, JSON.stringify(this._sanitizeForCache(user)));
    else localStorage.removeItem(this._SESSION_KEY);
  } catch {}
},
```

호출자가 받은 user 객체는 그대로 — in-memory state 는 PII 포함. localStorage 만 sanitize. 첫 페인트 시 sanitized cache 사용 (PII 빈 상태로 표시) → boot.jsx 의 `refreshSession` 후 server 에서 full user 받아 setUser → MyPage 가 PII 표시.
