- 우선순위: **속도감 ↑ + 기능 회귀 0**

## 작업 항목

### A. Admin lazy-load (가장 큰 효과 — 비-admin 99% 트래픽 대상)
- index.html 에서 4개 admin 스크립트 제거 (AuthAdminPage / AdminDesignHub / AdminContentEditors / AdminShared)
- boot.jsx 에 `loadAdminScripts()` 함수 추가 — route === 'admin' OR user.isAdmin/SuperAdmin 진입 시 동적 주입
- script.onload 까지 await + 로딩 fallback UI
- 안전장치:
  - 동일 src 중복 주입 방지 (idempotent)
  - 한 번 로드되면 메모리 캐시 (재진입 시 즉시 렌더)
  - 로드 실패 시 retry 1회 + 에러 페이지
- 효과: 비-admin 첫 페이지 로드에서 ~3.85MB raw / ~360KB gz 절감 + 파스/컴파일 시간 단축

### C. 워커 list endpoint Cache-Control
- 안전한 public read 만:
  - `/api/books` (GET) — 60s
  - `/api/columns` — 60s
  - `/api/lectures` — 60s
  - `/api/tours` — 60s
  - `/api/site-content` — 60s
  - `/api/faqs` — 300s
  - `/api/legal/*` — 300s
  - `/api/grades` — 300s
  - `/api/categories` — 300s
- **제외 (auth/사용자별)**: posts (admin draft 포함), notifications, auth/me, analytics, comments
- TTL 짧게(60s) 잡아 admin write 후 ~1분 내 stale 해소
- `Cache-Control: public, s-maxage=N` 헤더만 추가 → CF Edge 자동 캐시
- 안정성: 회원-불특정 데이터만, 인증 분기 없음

### Bonus 1: HomePage dataTick 분리 (안전, 코드 영역 작음)
- 현재 `dataTick` 1개에 4 events 묶여 → 어떤 stream 변경에도 5개 useMemo + 2개 sort 모두 다시 실행
- columnsTick / lecturesTick / toursTick / postsTick / booksTick 별도 state
- 각 useMemo 의 dep 를 자기 stream 만 의존
- 회귀 없이 불필요한 정렬/재계산 차단

### Bonus 2: handlePostsList N+1 제거 (안정 검증 후)
- 현재 public read 마다 `getCurrentUser` 호출 (sessions D1 lookup) → admin filter 용
- read-only path 에선 cookie 검사만으로 분기 (DB 쿼리 회피)
- ※ 인증 로직 직접 변경은 위험 — 별도 사이클로 분리, 이번엔 보류
