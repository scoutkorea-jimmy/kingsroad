# v00.288 — 전주한켠: 객실 선택 → 기간 살아보기 상품 + 문의

## 요청 (사용자)
전주한켠을 "객실 선택"이 아니라 **기간 상품**으로:
- 1주일 살아보기 — 190,000원
- 2주 살기 — 350,000원
- 1달 살기 — 550,000원

상품 추가 + **시작일 선택** + **문의**해달라고.

## 현재 구조 (pages/HangyeonPage.jsx, 552줄, 메인 번들)
- 단일 property(전주한켠) 페이지. site content `hangyeon.*` 에서 정보.
- 상단: 체크인~체크아웃 날짜범위 + 성인/아동 인원 바.
- 탭: 객실선택 / 위치·교통 / 숙소소개 / 시설 / 이용안내.
- 객실선택: `BGNJ_HANGYEON.day()` 서버 객실 카드 + HkBookingModal(견적·예약). PMS(워커+D1).
- 내 예약(HkMyBookings).

## 제약
- **워커 배포 금지 흐름**(메모리: 한켠 PMS 워커 배포는 사용자 수동). → 백엔드 무변경.
- 문의 전용 API 없음(booking 만 존재, 객실 요율 강결합 → 패키지에 부적합).
- → **프론트 전용**. 문의 채널 = 전화/이메일 prefill(deploy-free).

## 설계 (프론트 전용)
1. **기간 상품 정의**: 페이지 상수 `STAY_PACKAGES` 기본값(1주 19만 / 2주 35만 / 1달 55만, nights 7/14/30).
   `info.stayPackages`(site content) 있으면 override → 추후 admin 편집 여지.
2. **객실선택 섹션 → 기간 상품 섹션**으로 교체:
   - 상단 체크인~체크아웃/인원 바 제거(패키지엔 시작일만).
   - 상품 카드 3개(이름·기간·가격·설명) + 선택 강조.
   - **시작일 선택**(단일 날짜 — 기존 HkDatePicker 단순화 or date input).
   - 각 카드 "문의하기" → 문의 모달.
3. **문의 모달**: 선택 상품 + 시작일 요약 + 이름/연락처/메시지(선택) + 안내.
   제출 = 운영자 연락처로 **prefill** (mailto: contact 이메일 + tel: 전화), 요약 복사 버튼.
4. 탭 라벨 `객실선택` → `기간 상품`. `이용안내` 결제/취소 문구 → 문의 기반으로 조정.
5. HkMyBookings: 기존 PMS 예약 표시 — 유지(있으면 노출, 없으면 숨김). 무해.
6. 미사용 코드(HkBookingModal·HkRoomCard·HkHourSelect·day fetch 등)는 패키지 모델에서 안 쓰면
   제거 검토(단, 회귀 위험 최소화 — 우선 섹션 교체에 집중, dead 정리는 빌드 확인 후).

## 검증
- 빌드 + check-syntax + 헤드리스 `#/hangyeon`·`#/sleep` 마운트 + 콘솔 0.
- 문의 모달 열림/시작일/상품 선택/연락처 prefill 동작 확인.
- 회귀: 다른 공개 라우트 영향 없음(이 페이지만 변경).
