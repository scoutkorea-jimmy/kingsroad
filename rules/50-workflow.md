# 작업 절차 규칙

---

## 1. 작업 시작 전

1. **[handoff/ACTIVE.md](handoff/ACTIVE.md)** 를 읽습니다. 진행 중인 건이 있으면 그것부터 이어받습니다.
   **PC가 바뀌었다면 여기가 시작점입니다.**
2. 관리자 '오류 로그' 를 확인합니다. 미해결 오류가 있으면 우선 처리합니다 → [40-security.md](40-security.md)
3. [../CLAUDE.md](../CLAUDE.md) 라우팅 표에서 이번 작업에 해당하는 규칙 파일만 읽습니다.
   **전체를 훑지 않습니다.**
4. 새 작업이면 `ACTIVE.md` 에 지시 내역·범위·체크리스트를 쓰고 시작합니다.

## 2. handoff 운영

작업 기록은 `rules/handoff/` 한 곳에만 남습니다. (이전의 `plans/` 폴더는 여기로 흡수됐습니다.)

| 파일 | 역할 |
|---|---|
| `ACTIVE.md` | 지금 진행 중인 건 **하나**. 없으면 "없음" |
| `INDEX.md` | 전체 목록 + 상태 한 줄 |
| `done/` | 완료된 건 |

### 흐름

1. **시작** — `ACTIVE.md` 에 다음을 씁니다.
   - 사용자 지시 **원문 요지** (해석이 아니라 실제로 뭐라고 했는지)
   - 확정된 선택과 그 근거
   - **보류된 것** — 나중에 하기로 한 것, 왜 보류인지
   - 범위 / 비범위
   - 진행 체크리스트
2. **진행 중** — 체크박스를 갱신합니다. 중간에 내린 판단과 조사 결과도 함께 남깁니다
   (다음 사람이 같은 조사를 반복하지 않도록).
3. **완료** — 상태를 `완료`로, 완료일 기입 → `done/YYYY-MM-DD-<주제>.md` 로 이동 →
   `INDEX.md` 에 행 추가 → `ACTIVE.md` 를 "없음"으로 초기화.

### 무엇을 남기나

작업을 넘길 때 네 가지를 남깁니다 — **무엇을 바꿨는지 / 무엇이 아직 남았는지 /
어떤 가정을 했는지 / 어떤 리스크가 있는지.**

단순 결과만이 아니라 **그렇게 하게 된 계기와 배경**을 함께 씁니다.
나중에 다른 AI나 사람이 맥락을 보고 이어서 개발할 수 있어야 합니다.

## 3. 파일명

1. 파일명은 영어를 기본으로 합니다 (handoff 문서는 `YYYY-MM-DD-<topic>.md`).
2. 짧고, 예측 가능하고, 의미가 분명해야 합니다.
3. 기존 파일명 변경은 영향 범위를 설명할 수 있을 때만 합니다.

## 4. 기준 문서

1. 구현 상태의 1차 기준은 **저장소 안의 실제 코드**입니다. 문서가 아닙니다.
2. 규칙의 기준은 `rules/` 입니다.
3. 백로그·우선순위의 기준은 [../ROADMAP.md](../ROADMAP.md) 입니다.
4. 기능 정의·운영 매트릭스는 [../docs/kms.md](../docs/kms.md) 이며, 관리자 KMS 화면과 동기됩니다.
5. **문서와 코드가 충돌하면 같은 작업 안에서 둘 중 하나를 반드시 갱신합니다.**
6. 디자인 결정은 `rules/20-design.md` · `design/tokens.md` · `AdminDesignHub.jsx` **셋을 함께** 갱신합니다.

## 5. AI 간 협업

1. 구조 변경을 제안하기 전에 **기존 코드를 먼저 읽습니다.**
2. 다른 AI가 만든 작업을 사용자가 요청하지 않는 한 덮어쓰거나 되돌리지 않습니다.
3. 이미 있는 규칙·구조가 있으면 중복 생성보다 **확장**을 택합니다.
4. 가능하면 같은 파일을 여러 AI가 동시에 수정하지 않습니다.

## 6. 비개발자 설명 규칙

이 프로젝트의 운영자는 비개발자입니다.

1. 어려운 용어를 그대로 쓰지 않고 쉬운 말로 먼저 설명합니다.
2. **무엇이 바뀌는지 → 왜 필요한지 → 어떤 영향이 있는지** 순서로 말합니다.
3. 기술적 세부는 필요할 때만 덧붙입니다.
4. 문제가 생기면 원인보다 **체감되는 현상**을 먼저 설명합니다.
5. 완료되지 않은 기능은 현재 어디까지 됐는지 분명히 밝힙니다.

## 7. 작업 종료 전 체크리스트

- [ ] 지시받은 범위를 다 했는가. 못 한 게 있으면 명확히 기록했는가
- [ ] `ACTIVE.md` 를 갱신했는가
- [ ] 문서와 코드가 어긋나지 않는가 (특히 디자인 3종)
- [ ] 목업·미완성 동작을 분명히 표시했는가
- [ ] `git status` 를 확인했는가 — 관련 없는 파일이 섞이지 않았는가
- [ ] 버전 3종 동기를 했는가 (코드 변경 시) → [30-release.md](30-release.md)
- [ ] `node tools/check-syntax.mjs` · `node tools/build.mjs` 가 통과하는가
- [ ] commit + push 했는가
- [ ] 오류 로그에 본인 작업으로 인한 회귀가 없는가
