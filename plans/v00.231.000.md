# v00.231.000 — 데이터 사라짐 방어 (refresh 가드 + 진단 로그)

## 사용자 보고
> 데이터들이 자꾸 간혹 사라지는데 사라지지 않게 수정해. 이거 제일 중요하다

## 진단

`data.js` 의 모든 `BGNJ_*.refresh*()` 헬퍼가 다음 패턴이었음:

```js
async refresh() {
  try {
    const { lectures } = await window.BGNJ_API.lectures.list();
    this._lectures = (lectures || []).map(this._toLecture);  // ← 위험
  } catch {}
}
```

문제: `lectures` 가 `null`/`undefined`/`{}` 같은 비-배열 응답이면 `|| []` 가 빈
배열로 평가 → 캐시를 **빈 배열로 덮어씀** → 화면에서 데이터 사라진 것처럼 보임.

발생 시나리오:
- 워커가 D1 일시 오류 시 `{ lectures: null }` 응답
- 워커 응답 형식 변경 시 (예: `{ items: [...] }` 반환) 키 mismatch
- 다른 탭에서 `BGNJ_BROADCAST` 발화 → 모든 탭이 refresh 호출 → 그 중 한 탭이
  401/네트워크 일시 오류 → 응답 파싱 실패 → 빈 배열 덮어씀
- catch 블록이 silent 라 어드민/사용자 모두 원인 모름

## 수정

### 17곳 refresh 헬퍼 일괄 가드

각 `(arr || []).map(...)` 패턴을 다음으로 교체:

```js
if (!Array.isArray(arr)) {
  try { console.warn('[BGNJ_X.refresh] non-array — cache preserved'); } catch {}
  return this._cache.slice();
}
this._cache = arr.map(...);
```

### 진단 로그

각 가드 fail 시 `console.warn('[BGNJ_X.method] non-array — cache preserved')`
출력. 사용자/어드민이 콘솔 확인 시 어떤 도메인이 실패했는지 즉시 식별 가능.

silent fail 의 가시화 — "데이터 사라짐" 재발 시 console.warn 카운트 + 메시지로
원인 추적 가능.
