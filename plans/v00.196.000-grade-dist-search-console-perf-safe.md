# v00.196.000 — 회원 등급별 분포 + 검색콘솔 입력 + 홈페이지 안정적 성능 개선

## 사용자 요청 원문
- "대시보드에 회원 등급별 분포 현황도 넣어주고"
- "홈페이지 반응성을 확장시킬 수 있도록 처리해줘"
- "시스템에 구글과 네이버 등의 서치 콘솔과 최신화가 가능한 api입력 페이지들을 만들어줘"
- "퀵윈모다 보다 안정적인 형태로 진행해줘. 기능에 문제가 있어선 안됨"

## 의사결정 — 안정성 우선
사용자 원칙 = 기능 회귀 없이 점진 개선. 이전에 제안했던 5개 옵션(A-E) 중 functional risk 가 가장 작은 것만 선택:

| 옵션 | 안정성 | 효과 | 채택 |
|---|---|---|---|
| A. admin 번들 lazy-load | 중간 (UMD→ESM 전환 필요) | 대 | ❌ 보류 |
| B. sourcemap 프로덕션 제거 | 매우 높음 (single line) | 중 (-880KB gz) | ✅ |
| C. 워커 list endpoint Cache-Control | 중간 (stale data risk) | 중 | ❌ 보류 (write 후 무효화 처리 필요 — 안정성 위협) |
| D. 폰트 preload | 매우 높음 | 소-중 | ✅ |
| E. ScrollToTop throttle + memo | 높음 | 중 | ✅ |

## 작업 항목

### 1) 회원 등급별 분포 대시보드
- AdminShared 의 `RankedBarList` 재사용 (DRY)
- 데이터: `allUsers` × `BGNJ_STORES.grades` 매핑
- 위치: 회원가입 추이 차트 옆 또는 하단

### 2) 검색콘솔 입력 패널 (사이트 설정 → 새 sub-tab "검색엔진")
신규 컴포넌트 `SearchConsoleAdminPanel`:
- Google Site Verification (meta content 입력)
- Naver Site Verification
- Bing Webmaster
- 사이트맵 URL 표시 (자동 생성: `${origin}/sitemap.xml`)
- "Search Console 열기" 버튼들 (각 콘솔 새창 — OAuth 회피)
- "Sitemap Ping" 버튼: Google `https://www.google.com/ping?sitemap=` (HEAD 만 — CORS 우회용 새창 또는 fetch no-cors)
- 데이터: site_content_kv.searchConsole 객체에 저장 (BGNJ_SITE_CONTENT.saveSection 재사용)
- 검증 meta 는 `applyHead` 가 이미 `customMetas` 등 처리 → 추가 또는 별도 키 처리

### 3) 안정적 성능 개선
- **B. sourcemap 제거**: `tools/build.mjs` esbuild 옵션 → `sourcemap: false`
- **D. 폰트 preload**: index.html 에 핵심 weight woff2 `<link rel="preload" as="font">`
- **E1. ScrollToTop throttle**: `requestAnimationFrame` 한 번만 큐잉 (이미 보일 때 early-return 추가)
- **E2. React.memo**: Nav, Footer, ScrollToTop, CookieConsent 에 memo 래핑
