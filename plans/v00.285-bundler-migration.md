## 배경 (피드백)
"홈페이지가 스파게티 코딩" 피드백. 코드 직접 진단 결과 — 폴더/페이지 단위 정돈은 돼 있으나
**체감 주범은 모듈 시스템의 부재**다.

### 진단 (실측)
| 신호 | 실측 |
|---|---|
| 번들러/모듈 없음 | `tools/build.mjs` 는 per-file `esbuild.transform` → IIFE 래핑. **번들링 안 함** |
| 전역 네임스페이스 결합 | `window.X = X` 내보내고 `const X = window.X` 받기 — 전체 **1,100회+** (AuthAdminPage.jsx 453회) |
| 거대 단일 파일 | `pages/AuthAdminPage.jsx` 9,273줄 / 선언 452개 |
| 빌드 산출물 중복 커밋 | `.jsx` + `.js` 둘 다 git 커밋 → 모든 PR diff 2배 |
| 수동 캐시버스팅 | `index.html` script 20여 개 `?v=` 수동 동기 |

### 근본 원인
파일 간 의존성을 `import` 대신 **전역 + 로딩순서**로 표현 → (1) 의존 그래프 불투명,
(2) `index.html` 줄 순서가 숨은 의존성, (3) `const X = window.X` 보일러플레이트 범람.

## 목표
per-file IIFE transpile + 전역 네임스페이스 → **단일 엔트리 import/export 번들**.
React/ReactDOM/Tiptap 은 CDN external 유지. GitHub Pages 배포·CSP 무중단.

## 제약 (반드시 보존)
- **배포**: GitHub Pages, `.github/workflows` 가 `path: .` 로 레포 전체 업로드. 도메인 `bgnj.net`.
  → 번들 산출물이 **배포 시점에 존재**해야 함. CI 에 빌드 스텝 추가가 전제.
- **CSP**: 인라인 script sha256 해시 의존 (`tools/csp-hashes.mjs` 자동화 존재). 번들 후 재생성.
- **의도된 런타임 전역 API (남긴다, 모듈화 대상 아님)**:
  `window.BGNJ_API` · `window.BGNJ_TOAST` · `window.BGNJ_VERSION` · `window.ADMIN_*` 데이터 + Tiptap importmap.
- **pre-commit 훅**: stamp-datetime → csp-hashes → check-version → build → check-syntax. 5단계 순서 유지/조정.
- **데이터 손실 안티패턴 금지** (메모리): `(data||[]).map()` 금지, Array.isArray 가드.

## 핵심 전략 — 점진적 공존 (leaf→root, 무중단)
빅뱅 금지. esbuild **bundle 모드**로 전환하되, 미변환 파일과 공존하도록 모듈을 하나씩 전환:
- 변환된 모듈은 전환기 동안 **`export` + `window.X = X` 병행** (구 소비자 호환).
- 소비 측은 의존 모듈이 변환되면 `import`, 아직이면 `window.X` 폴백.
- 의존 없는 leaf(`components/`)부터 → `pages/` → `pages/admin/` → `boot`.
- 각 단계가 독립 배포 가능 + 롤백 가능.
